## 1. 我對需求的理解（請先檢查這段）

- 總召要的是「不用跑來跑去就知道現在進行到哪」，M1 只先證明**總召按一下，相關的人 2 秒內就看到**這條路是通的。
- 新秘要的不是「看到時程表」，而是**雙手不空時抬頭瞄一眼，就知道離下一個交付點還有幾分鐘**。所以新秘畫面只有一個極大的數字，沒有任何要點的東西。
- 第一場的婚前準備（建立活動、角色、Rundown、發連結）由開發者自己用指令完成，不做介面。
- 連結本身就是身分：拿到新秘連結的人只看得到新秘的環節，拿到錯的或過期的連結會看到明確的說明，而不是空白或錯誤畫面。

## US-M-0 婚前準備（以指令完成）

**身為** 開發者（第一場的活動建立者），**我希望** 用伺服器端指令建立活動、角色與 Rundown 並取得各角色的連結，**以便於** 不必等管理介面就能讓總召與新秘開始使用。

| 編號 | 驗收條件 |
| --- | --- |
| US-M-0.1 | **Given** 資料庫已初始化，**When** 執行 `bethere create-event`（名稱、日期、時區），**Then** 建立 Draft 活動與唯一的 Master 角色，終端機只顯示一次 Master 連結與復原碼，資料庫只存兩者的雜湊 |
| US-M-0.2 | **Given** 一份 Rundown 檔（每列：順序、標題、表定開始、長度、是否固定、指派角色、角色備註），**When** 以指令匯入，**Then** 建立所有 Cue 與指派；任一列不合法（時間格式、角色不存在、順序重複）時整份不寫入，並列出錯誤列 |
| US-M-0.3 | **When** 以指令新增角色（例如「新秘」，類型 Stylist），**Then** 終端機只顯示一次該角色的連結 |
| US-M-0.4 | 指令的輸出只到終端機，不寫入任何日誌（`access-control.md` 第 2 節） |
| US-M-0.C1 | 開發者照 README 的步驟，15 分鐘內從空資料庫準備好一場可彩排的活動 |

## US-M-1 掌握全域動態（M1 部分）

**身為** 總召，**我希望** 在平板上一眼看清完整時間軸與目前進行的環節，**以便於** 不必到處確認進度。

| 編號 | 驗收條件 |
| --- | --- |
| US-M-1.1 | **Given** Master 連結，**When** 開啟，**Then** 看到全部 Cue，依順序列出有效時間（`HH:MM`）、標題、狀態圖示（`✔` 完成、`▶` 進行中、`○` 待辦、`■` 固定） |
| US-M-1.2 | 目前進行中的 Cue 顯示在右欄最上方，含已進行時間與預計長度（`screen-design.md` 3.1） |
| US-M-1.3 | 時間軸自動捲動到目前的 Cue，下一個 Cue 保持可見 |
| US-M-1.4 | 畫面每 2 秒更新一次；另一台總召裝置的操作在 3 秒內反映（E2） |
| US-M-1.C1 | 總召單手拿著 iPad 橫放，在昏暗的室內 3 秒內說出「現在進行到哪個環節、下一個是什麼」 |

## US-M-3 推進流程

**身為** 總召，**我希望** 在環節轉換時按一個大按鈕推進狀態，**以便於** 系統高亮目前進度並即時讓相關的人知道。

| 編號 | 驗收條件 |
| --- | --- |
| US-M-3.1 | **Given** 活動為 Draft 且今天是活動日（依活動時區），**When** 總召按「開始活動」，**Then** 活動變為 Live；非活動日時按鈕停用並說明原因 |
| US-M-3.2 | **Given** 活動為 Live，**When** 按「推進」，**Then** 目前進行中的 Cue 變為完成（記錄實際結束時間），下一個待辦的 Cue 變為進行中（記錄實際開始時間）；同一時間只有一個進行中的 Cue |
| US-M-3.3 | 推進不需要二次確認；按下後按鈕停用約 1 秒，防止連點 |
| US-M-3.4 | **Given** 兩台總召裝置，**When** A 推進後、B 的畫面尚未更新就按推進，**Then** B 的操作被拒絕，畫面顯示「畫面已更新，請重新確認」並自動刷新（S6） |
| US-M-3.5 | 每次推進都寫入操作紀錄（誰、何時、改了哪些 Cue） |
| US-M-3.C1 | 總召單手拇指在 iPad 上一次點擊完成推進，不會誤觸其他按鈕 |

## US-ST-1 螢幕常亮與免手持倒數

**身為** 新秘，**我希望** 開啟網頁後螢幕保持常亮，並以極大字體顯示離下一個交付點的倒數，**以便於** 手拿工具抬頭瞄一眼就能掌握節奏。

| 編號 | 驗收條件 |
| --- | --- |
| US-ST-1.1 | 倒數目標是「指派給新秘、狀態為待辦、順序最前」的 Cue；倒數 = 它的有效開始時間 − 現在（以伺服器時間校正） |
| US-ST-1.2 | **When** 總召推進，使下一個交付點改變，**Then** 新秘的倒數在 3 秒內改指向新的目標（E2） |
| US-ST-1.3 | 剩餘 > 15 分為暗底、5～15 分琥珀色、< 5 分紅色並改為「分:秒」、逾時為紅色閃爍並顯示「已逾時 N 分」；每種狀態同時有文字 |
| US-ST-1.4 | 沒有下一個交付點時：若有指派給新秘的進行中 Cue，顯示「〈標題〉進行中」；都沒有則顯示「今日任務已完成」 |
| US-ST-1.5 | 活動尚未開始時顯示「活動尚未開始」 |
| US-ST-1.6 | 沒有取得螢幕常亮時，全螢幕顯示「點一下，保持螢幕常亮」；點任何位置後申請常亮，取得後提示消失 |
| US-ST-1.7 | 倒數畫面上除了常亮提示層，沒有任何需要點的東西 |
| US-ST-1.C1 | 手機平放在化妝台上、距離 40～60 公分，新秘不用手碰，3 秒內看得出剩幾分鐘 |
| US-ST-1.C2 | 放著 30 分鐘，螢幕不會自動關閉（iPhone Safari，必要時點一下提示層） |

## US-X-1 連結即身分

**身為** 任何收到連結的人，**我希望** 點開連結就看到屬於我的畫面，**以便於** 不必註冊或登入。

| 編號 | 驗收條件 |
| --- | --- |
| US-X-1.1 | 開啟 `#t=` 連結即依角色顯示畫面：Master → 主控台，Stylist → 新秘模式 |
| US-X-1.2 | 新秘的回應只包含指派給新秘的 Cue 與新秘自己的角色備註；不含其他角色的 Cue、備註或角色清單（F3，伺服器端過濾） |
| US-X-1.3 | 錯誤或已撤銷的連結顯示「連結已失效，請向總召索取新連結」 |
| US-X-1.4 | 活動結束後（活動日隔天 04:00）顯示「活動已結束，感謝你的協助」，回應不含任何活動資料 |
| US-X-1.5 | 新秘連結呼叫總召的操作（例如推進）會被拒絕；拒絕的回應不會讓新秘的畫面變成「連結已失效」 |
| US-X-1.6 | 伺服器或資料庫出錯時，畫面不會顯示「連結已失效」或「活動已結束」 |
| US-X-1.C1 | 從 LINE 收到連結，以 Safari 開啟、加入主畫面後再從主畫面開啟，仍然是同一個角色的畫面 |
