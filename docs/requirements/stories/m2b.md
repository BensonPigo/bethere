## 1. 我對需求的理解（請先檢查這段）

- M2b 不新增核心價值，而是補上活動當天一定會碰到的情況；做完之後，M3 只剩上線與維運。
- **就位**是「人到了沒」，每個角色一個狀態，不是每個 Cue 一個。總召在主控台看到誰到了、誰還沒，必要時替沒手機可按的人代打；打卡不會讓總召的操作被「畫面已更新」擋下（ADR-0023）。
- **攝影、音控**用快速瞄畫面：手機從口袋拿出來 2 秒，看「下一個與我有關的環節、還有幾分鐘、備註」。
- **離線唯讀**：開過頁面的裝置在斷網或伺服器停擺時，仍顯示最後的時程、倒數照跑，並明確標示「離線中」；總召離線時不能操作。LINE 內建瀏覽器離線打不開是已知限制（ADR-0010），不在 M2b 解決。
- **撤銷與重發**：廠商把連結轉傳出去、或手機掉了，總召在主控台當場換一條新連結，舊的 2 秒內失效。新連結由總召自己用 LINE 傳，系統不代發。
- **新增與略過**：現場臨時加一個環節（例如「長輩致詞」）、或取消一個環節，總召在主控台完成，相關的人自動看到。
- **快照條件請求（304）**：內容沒變時伺服器只回「沒變」，省流量；使用者看不出差別，以自動測試驗證。
- 以下三點待 PO 決定（見最後一節），草稿先寫建議值。

## US-M-6 略過 Cue

**身為** 總召，**我希望** 取消的環節可以略過，**以便於** 推進時不必經過它，而且仍留下紀錄。

| 編號 | 驗收條件 |
| --- | --- |
| US-M-6.1 | **Given** 活動為 Live、某 Cue 為 Pending，**When** 總召在 Cue 詳情點「略過」，**Then** 該 Cue 變為 Skipped，`eventVersion` + 1，寫入 `cue.skip` 操作紀錄 |
| US-M-6.2 | 推進跳過 Skipped 的 Cue，直接開始下一個 Pending |
| US-M-6.3 | 進行中、已完成、已略過的 Cue 不能略過（422）；Draft 階段不能略過 |
| US-M-6.4 | 「復原上一步」可撤銷略過，Cue 回到 Pending；復原按鈕顯示「撤銷：略過『…』」 |
| US-M-6.5 | 被略過的 Cue 從角色的「下一個與你有關的 Cue」與新秘倒數中消失；時間軸上以 `⊘` 淡化顯示 |
| US-M-6.6 | 略過帶版本號；版本不符時被拒絕（同 US-M-2.7） |

## US-M-7 撤銷與重發角色連結

**身為** 總召，**我希望** 連結外流或對方換了人時，當場讓舊連結失效並拿到新連結，**以便於** 不必找開發者。

| 編號 | 驗收條件 |
| --- | --- |
| US-M-7.1 | **When** 總召對某角色按「重發」並二次確認，**Then** 舊 Token 撤銷、建立新 Token，在同一交易內完成；回應只這一次帶新連結明文，畫面顯示新連結與「複製」按鈕 |
| US-M-7.2 | **When** 按「撤銷」並二次確認，**Then** 該角色沒有任何有效 Token；之後可再「重發」 |
| US-M-7.3 | 持舊連結的裝置在下一次輪詢收到 `invalid`，清除本機快照並顯示「連結已失效，請向總召索取新連結」 |
| US-M-7.4 | 不能對 Master 角色撤銷或重發（Master 只能以復原碼換發）；非 Master 呼叫一律 403 |
| US-M-7.5 | 目標角色屬於別的活動時回 404，不帶 `result`（同 `api.md` 第 6 節「帶 id 的請求」） |
| US-M-7.6 | 撤銷與重發都寫入操作紀錄（誰、何時、對哪個角色），不記錄 Token 或其雜湊；不改變 `eventVersion` 以外的 Cue 狀態，也不是「復原上一步」的步驟 |
| US-M-7.7 | 二次確認的文字說明「舊連結將立即失效，對方需要新連結」 |
| US-M-7.C1 | 總召在 iPad 上 30 秒內完成「重發 → 複製 → 貼到 LINE 傳出」 |

## US-M-8 活動中新增 Cue 與改派角色

**身為** 總召，**我希望** 現場臨時加的環節能指派給相關的人，**以便於** 他們不必靠口頭通知（ADR-0021）。

| 編號 | 驗收條件 |
| --- | --- |
| US-M-8.1 | **Given** 活動為 Live，**When** 總召輸入開始時間、長度、標題，選擇插在哪個 Cue 之後並確認，**Then** 新 Cue 的 `scheduledStart` = 輸入時間、`offsetMin = 0`、狀態 Pending；插入位置之後的 `seq` 依序加一，維持唯一、連續；單一交易，`eventVersion` + 1 |
| US-M-8.2 | 新增時可同時指派角色與角色備註 |
| US-M-8.3 | **Given** Cue 為 Pending，**When** 總召新增或移除指派，**Then** 立即生效；進行中、已完成、已略過的 Cue 不能改指派（422） |
| US-M-8.4 | 新增與改派寫入操作紀錄（`rundown.insert`、`rundown.assign`），**不是**「復原上一步」的步驟；插入 Cue 後，之前的平移仍可復原（ADR-0021「之後要注意」） |
| US-M-8.5 | 新增與改派帶版本號；版本不符時被拒絕 |
| US-M-8.6 | 任一 Pending Cue 的 `effectiveStart` 早於 `seq` 在它前面最近一個未略過 Cue 時，主控台在該 Cue 旁顯示 `⚠`「時間早於前一個環節 HH:MM」，不阻擋（`data-model.md` 4.2 第 5 步） |
| US-M-8.7 | Live 階段可改既有 Cue 的標題與公開備註；不能改既有 Cue 的 `scheduledStart`、長度、固定（`access-control.md` 第 4 節） |
| US-M-8.C1 | 總召在 iPad 上 30 秒內新增「長輩致詞」並指派給音控 |

## US-X-5 就位打卡（本人）

**身為** 廠商，**我希望** 到場時按一下就讓總召知道我到了，**以便於** 總召不必打電話確認。

| 編號 | 驗收條件 |
| --- | --- |
| US-X-5.1 | 快速瞄畫面底部固定「我已就位」；打卡後變為「已就位 ✔（取消）」 |
| US-X-5.2 | 免手持畫面：首次載入時，與「點一下，保持螢幕常亮」合併詢問一次是否就位；倒數畫面上沒有打卡按鈕（`screen-design.md` 第 5 節） |
| US-X-5.3 | 打卡只能針對自己的角色：請求不帶 `roleId`，角色取自 Token；Host 與 Master 呼叫本人打卡回 403 |
| US-X-5.4 | 重複打卡不產生重複紀錄；取消後可再打卡 |
| US-X-5.5 | 打卡在 Draft 與 Live 都可以（活動前一天先到場佈置的情況）；活動結束後回 `ended` |
| US-X-5.6 | 角色快照的 `myCheckIn` 反映目前是否就位；Master 快照的各角色就位狀態在下一次輪詢更新 |
| US-X-5.7 | 離線時打卡按鈕停用並說明原因，不排隊、不重送（`sync-and-offline.md` 第 6 節） |

## US-X-6 快速瞄畫面（攝影、音控）

**身為** 攝影或音控，**我希望** 手機拿出來 2 秒就知道下一件事與還有幾分鐘，**以便於** 不錯過卡位或放音樂的時間。

| 編號 | 驗收條件 |
| --- | --- |
| US-X-6.1 | `bethere add-role` 接受 Media、StageAV；預設畫面為快速瞄，可指定為免手持（ADR-0025） |
| US-X-6.2 | 置頂卡片為「下一個與你有關的 Cue」（指派給自己、Pending、`seq` 最小）：時間、標題、倒數、角色備註（Media、StageAV 預設展開）；平移過的顯示原時間（ADR-0028） |
| US-X-6.3 | 卡片下方列出之後 2～3 個與自己有關的 Cue |
| US-X-6.4 | 目前環節一行：**建議**顯示進行中 Cue 的標題（不論是否指派給自己，與 Host 相同只有標題）；待 PO 決定（最後一節第 1 題） |
| US-X-6.5 | 角色快照只含指派給自己的 Cue；Media、StageAV 的快照鍵集合以測試固定，與 Stylist 相同（加上 US-X-6.4 若採用的欄位） |
| US-X-6.6 | StageAV 的角色備註以等寬字體顯示，長內容換行不截斷 |
| US-X-6.7 | 自己的 Cue 都已完成或略過時，卡片顯示「你的環節都完成了」 |
| US-X-6.C1 | 攝影把手機從口袋拿出來，2 秒內說出「下一個是什麼、還有幾分鐘」 |
| US-X-6.C2 | 音控在昏暗的控台旁，看得清備註中的音檔名稱 |

## US-X-8 離線唯讀

**身為** 任何角色，**我希望** 斷網或伺服器停擺時仍看得到最後的時程，**以便於** 進地下室宴會廳不會變成空白畫面（NFR-3）。

| 編號 | 驗收條件 |
| --- | --- |
| US-X-8.1 | 約 10 秒沒有成功的輪詢即顯示「離線中，資料更新於 HH:MM」；恢復後第一次成功輪詢即以伺服器快照覆蓋並隱藏 |
| US-X-8.2 | 離線超過 5 分鐘追加「倒數可能不準」 |
| US-X-8.3 | 離線期間倒數依最後的時鐘偏差繼續跑 |
| US-X-8.4 | 總召離線時推進、平移、復原、略過、新增、改派、代打卡、重發、撤銷全部停用並顯示原因 |
| US-X-8.5 | 只有 HTTP 200、JSON、可解析且 `result` 為 `invalid` 或 `ended` 才清除本機快照；401、403、5xx、逾時、Wi-Fi 登入頁（HTML）、無法解析都只算離線（NFR-6，以前端單元測試逐項固定） |
| US-X-8.6 | 開啟頁面時先以本機快照渲染，再背景輪詢；`eventStatus = Live` 且 `serverTime` 超過 2 天的本機快照在開啟時刪除 |
| US-X-8.C1 | 已開過頁面的 iPhone（Safari 或主畫面）切到飛航模式後重新開啟連結，畫面顯示最後的時程與「離線中」，倒數照跑 |
| US-X-8.C2 | 伺服器停止 1 分鐘再啟動：各裝置顯示離線、恢復後自動更新，不需重新整理 |

## 技術工作

| 工作 | 內容 | 依據 |
| --- | --- | --- |
| 開放 Media、StageAV | `add-role` 接受兩種類型；權限表與快照依 `api.md` 第 4、5 節 | `api.md` 第 4 節 |
| 新端點 | 就位打卡與取消（本人）、代打卡與取消（Master）、略過、新增 Cue、改派、改標題與備註、撤銷、重發；寫入 `api.md` 第 3、4、6 節 | 本文件 |
| 快照追加 | 角色快照加 `myCheckIn`；Master 快照的 `roles[]` 加就位狀態與 `lastSeenAt`、加時間倒序警告；變更提示加 `assign` | `api.md` 第 5 節 |
| 快照條件請求 | ETag 為不含 `serverTime` 的內容雜湊（鍵順序固定）；`If-None-Match` 相同回 304；伺服器時間放回應標頭；`invalid`、`ended` 永不回 304；客戶端收到 304 保留快照、只更新時鐘偏差 | ADR-0023；`api.md` 5.7 |
| `invalid` 與 `ended` 不回 304 的測試 | 先拿到 ETag，再撤銷 Token 或讓活動結束，帶同一個 ETag 請求仍回 200 與 `result` | ADR-0023 |

**需要審查的部分**（`process/development-process.md` 第 5 節）：

- **Token 權限與資料外洩**：撤銷與重發、Media 與 StageAV 的快照內容（含 US-X-6.4 的決定）、打卡的歸屬檢查、新端點的權限表、304 不得繞過驗證。實作前 `security-reviewer` 一次，完成後 `verifier` 一次。
- **資料不遺失**：M2b 預計不需要遷移（`check_ins` 已在 `0001_init.sql`）；若實作中需要新欄位，依 ADR-0019 只新增、不改舊表，並列入同上的審查。

## 待 PO 決定

1. **攝影、音控能不能看到「目前環節」的名稱**（US-X-6.4；`api.md` 5.3 留給 M2b 決定）。建議：可以，只給標題，與 Host 相同。
2. **撤銷與重發放在哪裡**（US-M-7）。建議：放在主控台的角色選單，只顯示連結與「複製」，不做 QR Code（QR 屬 P1 的管理介面）。
3. **攝影、音控實測找誰**。
