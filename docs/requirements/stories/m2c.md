# M2c 婚前準備：故事與驗收條件

> 狀態：**PO 定稿（2026-10-24）**。
> M2c 目標（2026-11 底）：開發者建好一場空活動、把 Master 連結交出去之後，總召在電腦或平板上自己完成婚前的所有準備：編輯流程表、新增角色、產生連結與 QR Code、從試算表貼上整份流程表，並預覽每個角色會看到什麼；婚前改流程不必重建活動、不必重發連結（ADR-0031）。
> 編號：功能條件 `US-x-n.m`（自動測試），情境條件 `US-x-n.Cm`（PO 或真實使用者在真機上判定）。

## 1. 我對需求的理解（請先檢查這段）

- 使用的人是**總召**，用的是同一條 Master 連結。婚前通常在電腦上整理，也要能在 iPad 上改。新人或婚顧拿 Master 連結來準備也一樣。
- **活動開始前（Draft）什麼都能改**：環節的時間、長度、固定、標題、備註、順序、指派與角色備註，也能直接刪除環節。活動開始後（第一次推進）自動變回 M2b 的有限編輯，不能改時間、不能刪除，只能略過。
- 改完的流程表，所有角色**下一次輪詢就看到**，不需要重發連結。
- **新增角色**：總召取名字（例如「伴娘」「化妝師小美」），選一種畫面（免手持、快速瞄、平安儀表板），選要不要打卡，就產生一條連結，並附 QR Code，廠商可以當面掃。角色能改名；活動開始前能刪除，刪除時連結一併失效。權限仍由系統決定，總召不能讓其他角色推進或修改流程（ADR-0031）。
- **貼上匯入**：從 Excel 或 Google 試算表複製整份流程表貼上，先看預覽，錯誤的列標紅並寫出原因，確認後才寫入。
- **預覽**：總召選一個角色，看到那個角色畫面上的內容；預覽只能看，不會替那個角色打卡，也不算「有人在用這條連結」。

## US-M-10 Rundown 編輯器（Draft）

**身為** 總召，**我希望** 活動開始前在畫面上直接修改流程表，**以便於** 婚前流程改了，不必請開發者重建活動、也不必重發所有人的連結。

| 編號 | 驗收條件 |
| --- | --- |
| US-M-10.1 | Draft 階段，主控台有「編輯流程表」入口，進入以表格呈現所有 Cue：順序、開始時間、長度、標題、固定、指派角色、公開備註；角色備註展開後依角色分欄 |
| US-M-10.2 | 可修改既有 Cue 的開始時間、長度（0～1440 分）、固定、標題（1～100 字）、公開備註（≤500 字）、指派與角色備註；儲存後 `eventVersion` + 1，寫入操作紀錄 |
| US-M-10.3 | 可調整順序（拖曳，或上移／下移按鈕）；`seq` 保持唯一、連續 |
| US-M-10.4 | 可刪除 Cue（二次確認）；連同其指派一併刪除，後面的 `seq` 依序遞補 |
| US-M-10.5 | 可在任意位置新增 Cue（M2b 的新增沿用到編輯器） |
| US-M-10.6 | 即時驗證：標題必填；開始時間早於前一個未略過的 Cue 時顯示 `⚠`，不阻擋（固定 Cue 同樣只提示）；時間不在活動日當天時拒絕 |
| US-M-10.7 | 活動為 Live 時，編輯器只開放 M2b 的有限編輯，其他欄位唯讀並說明「活動已開始，時間請用平移」；結構性修改的請求一律回 422（伺服器強制，不只靠畫面） |
| US-M-10.8 | 已有平移紀錄（`offsetMin` 不為 0）的 Cue 改開始時間時，行為依 `api.md` 定案並以測試固定（見「技術工作」） |
| US-M-10.9 | 版本衝突沿用 `sync-and-offline.md` 第 3 節：另一台總召裝置先改了，儲存時收到 409，畫面提示「流程表已被更新」並載入最新內容，不覆蓋對方的修改 |
| US-M-10.10 | 非 Master 的 Token 呼叫編輯端點回 403；角色畫面只顯示自己被指派的 Cue（既有規則不變） |
| US-M-10.C1 | PO 在電腦上，把流程表中的一個環節延後 15 分、改一個標題、刪除一個環節，3 分鐘內完成，不需要看說明 |
| US-M-10.C2 | 總召在 iPad 上改了新秘的一個環節時間，新秘的手機在不重新整理的情況下顯示新時間 |

## US-M-11 在畫面上新增與管理角色

**身為** 總召，**我希望** 自己新增角色並取得連結，**以便於** 多請了一位攝影師或伴娘時，不必找開發者。

| 編號 | 驗收條件 |
| --- | --- |
| US-M-11.1 | 主控台的角色清單有「新增角色」：輸入名稱（1～50 字，同一活動內不可重複）、選畫面（免手持、快速瞄、平安儀表板）、選是否需要就位打卡 |
| US-M-11.2 | 新增後立即產生連結：只顯示這一次，附「複製」與 QR Code（US-M-13）；與 M2b 的重發相同，不做成可點開的連結。還沒有連結的角色（例如匯入時一鍵建立的，US-M-12.6）在角色清單顯示「連結未發」與「產生連結」 |
| US-M-11.3 | 權限由系統依選項決定，總召不能指定權限；新角色不能推進、平移或修改流程表；平安儀表板不能打卡 |
| US-M-11.4 | 角色可以改名；Draft 與 Live 都可以 |
| US-M-11.5 | 角色只能在 Draft 階段、活動日以前刪除（二次確認，ADR-0032）；同一交易內撤銷其連結、移除其指派與打卡，操作紀錄完整記錄被刪的內容（`data-model.md` Role） |
| US-M-11.6 | Master 角色不能新增、改畫面或刪除 |
| US-M-11.7 | 新增與改名不改變 `eventVersion`；刪除角色會移除指派，所以 `eventVersion` + 1 |
| US-M-11.8 | 每場活動的角色上限 50 個（NFR-1）；超過時回 422 並說明 |
| US-M-11.C1 | PO 在 iPad 上新增「伴娘」，把 QR Code 給另一支手機掃，從開始新增到對方畫面打開，1 分鐘內完成 |

## US-M-12 貼上 CSV 匯入

**身為** 總召，**我希望** 把試算表裡的整份流程表一次貼上，**以便於** 不必一個一個環節手動輸入。

| 編號 | 驗收條件 |
| --- | --- |
| US-M-12.1 | 編輯器有「貼上匯入」：貼上文字（逗號或 Tab 分隔，從 Excel／Google 試算表複製會是 Tab），欄位與 `stories/m1.md` US-M-0.2 的 CSV 相同 |
| US-M-12.2 | 先顯示預覽：每一列解析後的內容；不合法的列標紅並寫出原因（時間格式、長度、標題、角色不存在等），有錯就不能確認 |
| US-M-12.3 | 預覽由伺服器以同一套規則驗證（不寫入）；確認後在單一交易內寫入，任一列不合法就整份不寫入 |
| US-M-12.4 | 匯入只在 Draft 階段，**取代整份**流程表：確認前提示「現有的 N 個環節與指派將被取代」並二次確認；同一交易內刪除現有 Cue 與指派、寫入新的，寫入一筆操作紀錄，完整記錄被取代的內容（ADR-0032）；活動日當天不能匯入取代 |
| US-M-12.6 | 貼上的內容提到不存在的角色時，預覽列出缺少的角色，每個預設為「快速瞄、需要打卡」，可在預覽中改畫面與是否打卡；按一次「建立這些角色並匯入」即在**同一交易**內建立角色與寫入流程表，任一步失敗就全部不寫入；新角色的連結不在此時產生，之後在角色清單產生（顯示一次，US-M-11.2） |
| US-M-12.5 | 匯入的筆數上限 200 列、文字上限 100 KB；超過時拒絕並說明 |
| US-M-12.C1 | PO 從自己的 Google 試算表複製一份流程表貼上，一次成功；或錯誤訊息讓 PO 不需要問就知道要改哪裡 |

## US-M-13 連結的 QR Code

**身為** 總召，**我希望** 產生連結時一併看到 QR Code，**以便於** 廠商就在旁邊時，直接用手機掃就能打開。

| 編號 | 驗收條件 |
| --- | --- |
| US-M-13.1 | 新增角色（US-M-11.2）與重發連結（M2b）時，在「複製」旁顯示 QR Code |
| US-M-13.2 | QR Code 在伺服器產生（PNG data URI），與 Token 在同一個回應中，只出現這一次，不存入本機快照或任何儲存（`tech-stack.md` 2.1「QR Code」） |
| US-M-13.3 | 關閉對話框後無法再次顯示同一個 QR Code；要再給一次只能重發 |
| US-M-13.C1 | 用 iPhone 與 Android 手機的內建相機掃描 iPad 上的 QR Code，都能打開正確的角色畫面 |

## US-M-14 以某角色預覽

**身為** 總召，**我希望** 切換成某個角色看他的畫面，**以便於** 確認每個人看到的環節與備註是對的。

| 編號 | 驗收條件 |
| --- | --- |
| US-M-14.1 | 編輯器與角色清單有「預覽」：選一個角色後，以該角色的畫面（免手持、快速瞄、平安儀表板）顯示該角色的快照內容 |
| US-M-14.2 | 預覽用 Master 的 Token 向伺服器取得「以該角色視角」的快照，不使用、不產生該角色的 Token；快照內容與該角色自己看到的相同（同一個快照產生函式，以測試比對） |
| US-M-14.3 | 預覽只能看：打卡按鈕停用；不更新該角色的 `lastSeenAt`；不寫入任何資料 |
| US-M-14.4 | 畫面上方固定顯示「預覽：〈角色名稱〉看到的畫面」與「結束預覽」 |
| US-M-14.5 | 非 Master 呼叫預覽端點回 403；指定其他活動的角色回 404 |
| US-M-14.C1 | PO 用預覽檢查新秘與新人的畫面，不需要另一支手機就能說出「新秘下一個環節是什麼」 |

## 技術工作

| 工作 | 內容 | 依據 |
| --- | --- | --- |
| 新端點 | 編輯 Cue、調整順序、刪除 Cue、新增角色、改名、刪除角色、匯入預覽、匯入、角色預覽；寫入 `api.md` | 本文件 |
| 有平移紀錄的 Cue 改時間 | 決定改的是 `scheduledStart`（保留 `offsetMin`）還是把 `offsetMin` 歸零；以及與「復原上一步」的互動（編輯後是否還能復原之前的平移） | `data-model.md` 4.2；ADR-0015 |
| 「是否打卡」與角色類型 | 總召的選項（畫面、是否打卡）如何對應到角色類型或新欄位；若需新欄位，依 ADR-0019 只新增 | `data-model.md` Role；ADR-0019 |
| QR Code 函式庫 | 選定並鎖定版本（候選 `skip2/go-qrcode`） | `tech-stack.md` 2.1 |
| CLI 保留 | `add-role`、`import-rundown` 照常可用，與畫面使用同一套規則 | `stories/m1.md` US-M-0 |

**需要審查的部分**（`process/development-process.md` 第 5 節）：

- **Token 權限與資料外洩**：新增角色與產生連結、QR Code 不得留存、角色預覽不得變成「冒用角色」的途徑（不寫入、不更新 `lastSeenAt`）、新端點的權限表。
- **資料不遺失**：刪除 Cue、刪除角色、匯入取代整份都是破壞性操作，要二次確認、單一交易、操作紀錄；Live 時伺服器拒絕結構性修改。
- 實作前 `security-reviewer` 一次，完成後 `verifier` 一次。

## PO 決定

| 問題 | 決定（2026-10-24） |
| --- | --- |
| 婚前準備與新角色 | 分成 M2c、M2d，都在 M3a 之前（ADR-0031） |
| 建立活動 | 維持開發者以指令建立 |
| 自行新增角色 | 總召取名稱、選畫面、選是否打卡；不設定權限 |
| M2c 的內容 | 編輯器、新增角色、貼上匯入、QR Code、以某角色預覽 |
| 貼上匯入是取代整份還是加在後面 | 取代整份，只在 Draft，二次確認 |
| 匯入的角色不存在時 | 預覽列出，一鍵建立後一起匯入 |
| 破壞性修改無法還原（實作前安全審查 P1） | 完整記錄；活動日當天鎖住匯入取代與刪除角色（ADR-0032） |
