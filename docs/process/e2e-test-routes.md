# 端對端測試路線 (E2E Test Routes)

> 理由見 ADR-0029。
> 程式在 `web/e2e/routes.spec.ts`（活動的路線）與 `web/e2e/company.spec.ts`（婚顧公司的路線），每條路線對應一個 `test`；本文件是路線的正本，改路線時兩邊一起改。

---

## 1. 這是什麼

測試程式用 Safari 的引擎（WebKit）開啟模擬的 iPad（總召）與 iPhone（其他角色），照下表的步驟點按鈕、看畫面，判定每條路線過或不過。它只驗**功能是否正確**；「人用起來順不順」的情境條件（`US-x-n.Cm`）仍由 PO 或真實使用者在真機上判定（ADR-0027）。

每次執行都會建立 8 場日期為今天的測試活動，以及 2 場日期為明天的活動（給「婚前準備」與「現場工作」，因為匯入取代、刪除角色、取代賓客名單與檢核表在活動日當天會被鎖住，ADR-0032），每條路線用自己的一場，互不影響（「備援流程表」只讀取，與「新人儀表板」共用一場；「新人儀表板」的活動結束另用一場；「現場工作」用今天與明天各一場）。另外建立兩家婚顧公司（各有第一位成員，照 US-O-11.1 由後台的管理員連結建立），給兩條公司路線各用一家；活動以外的建立方式見第 3 節。每場都有總召、新秘、攝影、音控、新人、領班、機動組、接待（迎賓）、禮金九個角色。測試流程從 10 分鐘前開始，共 5 個環節；晚上會自動縮短間隔，所以 00:00～23:49（台北時間）之間都能執行。

## 2. 路線

依序執行：公司路線先，活動路線在後；「伺服器停擺」與「維護模式」會重啟服務，所以排在最後。

## 3. 怎麼執行

**第一次**（只做一次）：

```bash
export PROJECT=bethere-prod-0606                     # ops/gcp 的腳本都要先設定專案
cd web && npm ci && npx playwright install webkit   # 安裝測試用的瀏覽器
ops/gcp/e2e-setup.sh                                 # 在 VM 上設定測試服務，印出它的網址
```

**每次部署後**：

```bash
cd web && PROJECT=bethere-prod-0606 E2E_TARGET=vm E2E_BASE_URL=https://<測試服務網域> npm run e2e
```

**開發時先在本機跑**（從原始碼建置，不連 VM）：

```bash
cd web && npm run build && npm run e2e
```

結果：終端機列出每條路線過或不過；`web/e2e-report/index.html` 是報告，不過的路線附截圖與操作紀錄（`npx playwright show-trace <檔案>` 可逐步重播）。

公司路線取得登入的方式：公司與第一位成員由後台的 API 以管理員連結建立；成員的登入連結用 `issue-login-link` 指令取得（US-O-12.8），本機與 VM 都一樣。信裡的連結（「公司登入與同事」的「開啟信裡的連結」）只在本機驗證：本機服務以 `BETHERE_MAIL=log` 啟動，把信寫進服務日誌，測試從日誌讀；VM 的測試服務不寄信，這幾步略過，由演練涵蓋（US-CO-1.C1）。「公司的活動與主控台」的「已結束的活動」要把活動日期改到過去，畫面做不到，只在本機用 `sqlite3` 改測試資料庫，VM 略過；「新人儀表板」的活動結束同理。公司頁面約每 10 秒重讀一次，所以別位成員在清單看到新活動、被移除者看到「請重新登入」的等待上限是 15 秒；主控台之間的同步仍是 5 秒。

## 4. 規則

- 只對測試服務執行（`bethere-e2e`，自己的資料庫）；正式服務與資料庫一律不碰（ADR-0029）。
- 每次執行都重建測試資料庫，舊的測試活動不保留。
- 凍結期（活動前 7 天，`process/development-process.md` 第 3 節）與活動當天不執行。
- 新增功能時，若它屬於某條路線的情境，就把步驟加進那條路線；新的情境再開新路線，並更新本文件。
