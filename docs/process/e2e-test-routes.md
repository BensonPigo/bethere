# 端對端測試路線 (E2E Test Routes)

> 理由見 ADR-0029。
> 程式在 `web/e2e/routes.spec.ts`，每條路線對應一個 `test`；本文件是路線的正本，改路線時兩邊一起改。

---

## 1. 這是什麼

測試程式用 Safari 的引擎（WebKit）開啟模擬的 iPad（總召）與 iPhone（其他角色），照下表的步驟點按鈕、看畫面，判定每條路線過或不過。它只驗**功能是否正確**；「人用起來順不順」的情境條件（`US-x-n.Cm`）仍由 PO 或真實使用者在真機上判定（ADR-0027）。

每次執行都會建立 7 場日期為今天的測試活動，以及 2 場日期為明天的活動（給「婚前準備」與「現場工作」，因為匯入取代、刪除角色、取代賓客名單與檢核表在活動日當天會被鎖住，ADR-0032），每條路線用自己的一場，互不影響（「備援流程表」只讀取，與「新人儀表板」共用一場；「現場工作」用今天與明天各一場）。每場都有總召、新秘、攝影、音控、新人、領班、機動組、接待（迎賓）、禮金九個角色。測試流程從 10 分鐘前開始，共 5 個環節；晚上會自動縮短間隔，所以 00:00～23:49（台北時間）之間都能執行。

## 2. 路線

依序執行；「伺服器停擺」會停掉服務，所以排在最後。

| 路線 | 模擬的情境 | 對應的條件 |
| --- | --- | --- |
| 總召的一天 | 活動開始前略過並復原 → 第一次推進開始活動 → 延後 10 分並復原 → 新增「長輩致詞」指派給音控 → 把「敬酒」改派給音控 → 改標題 | US-M-2、US-M-3.6、US-M-4.6、US-M-6.3、6.4、US-M-8.1～8.3、8.7 |
| 廠商收到變更 | 攝影按「我已就位」、新秘第一次開啟時回答已到場，總召看到 → 攝影看到目前環節名稱 → 總召延後 10 分，攝影與新秘看到「時程已更新」→ 總召新增環節給攝影，攝影看到「新增環節」→ 音控的備註為等寬字體 | US-X-5.1、5.2、US-M-1.6、US-X-6.4、6.6、US-ST-2.1、2.2、US-X-7.1 |
| 連結外流 | 總召重發攝影的連結（只顯示文字與複製，不是可點的連結）→ 舊連結的手機顯示「連結已失效」→ 新連結可用 → 撤銷後新連結也失效 → 備援操作者在 `/recover` 輸錯復原碼看到「復原碼不正確」，再照紙本輸入（小寫、空格）換發總召連結 → 舊總召連結顯示「連結已失效」、新連結打開主控台；頁面不讀取網址上的 Token、復原碼不進網址 | US-M-7.1～7.3、US-O-3 |
| 斷網 | 攝影的手機斷網：顯示「離線中」、倒數照跑、打卡停用 → 斷網中重新開啟仍看得到時程 → 總召斷網時不能推進 → 恢復後不必重新整理就收到更新 | US-X-8.1、8.3、8.4、US-X-5.7；US-X-8.C1 的自動部分 |
| 新人儀表板 | 開始前顯示「活動尚未開始」→ 推進後「一切順利」與目前環節、沒有任何按鈕 → 延後 10 分顯示「延誤 10 分」→ 復原後回到「一切順利」 | US-H-1.1、1.4、1.5 |
| 備援流程表 | 總召從主控台開列印頁，印出全部 5 個環節與各角色備註 → 只印新秘的 3 個環節 → 攝影從自己的畫面印出 4 個環節，看不到新秘 → 新人的連結沒有可列印的流程表 | US-X-9.1～9.4 |
| 現場工作 | 明天的活動：總召貼上賓客名單與檢核表 → 接待輸入「陳」找到 5 桌並報到，總召看到 1／2 → 接待按「呼叫機動組」，機動組看到並按「我來」，接待看到處理中 → 禮金勾選一項，總召看到由誰完成 → 今天的活動：推進後領班看到「一切順利」並按「收到」，總召的時間軸顯示「領班收到」 | US-M-16.2、16.3、US-RC-1.2、1.6、US-RC-2.1、US-RN-1.1、US-CA-1.2、US-X-10.2、US-VL-1.1 |
| 婚前準備 | 明天的活動：在編輯器改環節的標題與長度，新秘自己看到 → 上移、刪除環節 → 新增角色「伴娘」，連結附 QR Code，手機打開就是伴娘 → 預覽新秘看到的畫面 → 貼上 Tab 分隔的整份流程表，缺少的「主持」一起建立 → 刪除伴娘，她的手機看到「連結已失效」 | US-M-10.2～10.4、US-M-11.1、11.2、11.5、US-M-12、US-M-13.1、US-M-14 |
| 伺服器停擺 | 停掉服務 60 秒（本機 15 秒）：各裝置顯示離線、總召不能操作、倒數照跑 → 重新啟動後自己恢復，總召推進後攝影收到 | US-X-8.C2 的自動部分 |

「→ 總召看到」「攝影看到」都限在 5 秒內（一次輪詢 2 秒，NFR-2 為 3 秒）；實際花的時間記在報告的 `propagation` 註記裡。

## 3. 怎麼執行

**第一次**（只做一次）：

```bash
cd web && npm ci && npx playwright install webkit   # 安裝測試用的瀏覽器
ops/gcp/e2e-setup.sh                                 # 在 VM 上設定測試服務，印出它的網址
```

**每次部署後**：

```bash
cd web && E2E_TARGET=vm E2E_BASE_URL=https://<測試服務網域> npm run e2e
```

**開發時先在本機跑**（從原始碼建置，不連 VM）：

```bash
cd web && npm run build && npm run e2e
```

結果：終端機列出每條路線過或不過；`web/e2e-report/index.html` 是報告，不過的路線附截圖與操作紀錄（`npx playwright show-trace <檔案>` 可逐步重播）。

## 4. 規則

- 只對測試服務執行（`bethere-e2e`，自己的資料庫）；正式服務與資料庫一律不碰（ADR-0029）。
- 每次執行都重建測試資料庫，舊的測試活動不保留。
- 凍結期（活動前 7 天，`process/development-process.md` 第 3 節）與活動當天不執行。
- 新增功能時，若它屬於某條路線的情境，就把步驟加進那條路線；新的情境再開新路線，並更新本文件。
