# ADR-0011：活動自動結束，伺服器端資料 90 天內消失

- 狀態：已接受
- 日期：2026-10-20
- 對應：`access-control.md` P4；`data-model.md` M9；`clarification.md` C5；`tech-stack.md` T10、T-F；需求 F5

## 背景

活動結束後連結不應繼續看得到流程與人員資料（F5）。原需求是「活動結束後 Token 失效、資料保留 90 天後刪除」。但只刪資料庫不夠：Litestream 備份、磁碟、GCS 的 soft delete 都會讓資料多留幾天。結束也不能依賴「有人記得按」，因為當天的新人就是開發者。

## 決定

- **結束時間不儲存**：`endsAt` = 活動日隔天 04:00（依活動時區），由 `eventDate` 即時算出。到時所有 Token 回「已結束」。Token 沒有自己的到期時間。
- 伺服器內的每日排程刪除 `endsAt` 已超過 **80 天**的活動（`secure_delete` 覆寫內容）。
- Litestream 快照間隔 24 小時、保留 72 小時；備份 bucket 關閉 soft delete、不開版本控制；不排程磁碟快照。
- 合計**伺服器端所有副本在 `endsAt` 後 90 天內消失**；第 85 天人工驗收。

## 考慮過的選項

| 選項 | 優點 | 缺點 |
| --- | --- | --- |
| 自動結束 + 資料庫 80 天、全部副本 90 天（採用） | 刪除承諾涵蓋備份 | 事後匯出期限從 90 天縮為 80 天 |
| 資料庫 90 天刪除（原 C5） | 照原需求 | 備份會多留數天，「90 天刪除」實際上不成立 |
| 總召手動按「結束活動」 | 彈性 | 忘了按，連結就一直有效 |
| GCS 生命週期規則自動刪備份 | 不需人工 | 資料庫閒置時可能把唯一的備份刪光 |

## 後果

- 好處：結束不需要排程器也不需要人；刪除承諾對所有伺服器端副本成立。
- 代價：主機要常駐到第 81 天，或在停機前手動刪除 VM、磁碟與備份。
- 之後要注意：裝置上的 `localStorage` 只在再次開啟時清除，紙本不在系統控制範圍。
