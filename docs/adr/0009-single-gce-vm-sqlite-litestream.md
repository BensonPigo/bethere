# ADR-0009：單一 GCE VM + SQLite + Litestream 備份

- 狀態：已接受
- 日期：2026-10-20
- 對應：`tech-stack.md` 2.1「資料庫」、第 3 節

## 背景

單場資料量極小（數十個 Cue、數十個角色），同時在線最多 50 台，約每秒 25 個請求。開發者自費，越省越好，且已有 Google Cloud 可用。台灣使用者，延遲越低越好。平移必須在單一交易內完成。當天沒有人能即時維運（ADR-0013），架構越少零件越好。

## 決定

- Google Cloud Compute Engine `asia-east1`（台灣），**恰好一台** `e2-micro`，Debian 12，10 GB 開機磁碟；區域性靜態 IP；自訂 VPC，對外只開 80、443，SSH 只經 IAP。
- **Caddy** 負責 TLS（Let's Encrypt），反向代理到只綁 `127.0.0.1` 的 Go 服務。
- **SQLite**（WAL）放在開機磁碟；讀寫分兩個連線池，寫入只有一條連線。
- **Litestream** 持續把資料庫複製到同區域的 GCS bucket；VM 以專屬服務帳號存取，不需要金鑰檔。
- 不使用容器。發行版（Go 執行檔、Litestream、Caddy）以版本號存在 GCS 發行版 bucket，上傳後不覆寫；部署與回退都是「改 VM metadata 的版本號並重啟服務」。
- 預估每月約 US$11～12。

## 考慮過的選項

| 選項 | 優點 | 缺點 |
| --- | --- | --- |
| 單一 GCE VM + SQLite + Litestream（採用） | 最便宜；零件少；台灣機房延遲低 | 單點故障，靠備份還原與離線快取兜底 |
| Fly.io + SQLite（2026-10-20 先選後改） | 部署簡單 | 開發者已有 Google Cloud 可用；GCE 有台灣機房 |
| Cloud Run + Cloud SQL | 免管主機 | 容器檔案系統是暫時的，部署時新舊實例並存會有兩個 SQLite 寫入者；改用 Cloud SQL 要重新設計資料層，成本更高 |
| 前面加 Google HTTPS 負載平衡器 | 託管 TLS | 每月約 US$18，對單一 VM 沒有必要 |
| 跨區域備援 | 區域故障也能服務 | 成本與維運複雜度大增；當天沒人能切換（見 ADR-0013） |

## 後果

- 好處：一台主機、一個檔案型資料庫、一個備份目標，故障時的恢復步驟可以寫成幾行指令。
- 代價：VM 或磁碟故障時要重建 VM 並從 GCS 還原（目標 15 分鐘），期間各端只剩離線快取與紙本。整個 `asia-east1` 故障時不切換區域，是刻意接受的風險。
- 之後要注意：專案裡**恰好一台 VM**，否則兩台都寫同一個備份會互相覆蓋；建立腳本在已有 VM 時拒絕執行。重建 VM 會重新簽憑證，同一網域每週最多 5 張，演練一律用另一個子網域。
