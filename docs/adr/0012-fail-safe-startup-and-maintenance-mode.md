# ADR-0012：失效安全：不自動建庫、維護模式

- 狀態：已接受
- 日期：2026-10-20
- 對應：`tech-stack.md` 2.1「逾時與錯誤」「不自動建庫」「維護模式」

## 背景

客戶端收到「無效」就會清掉本機快照（ADR-0010）。如果伺服器在還原失敗時悄悄起了一個空資料庫，所有 Token 都查無資料，全場裝置會同時收到「無效」，把唯一的離線備份清光。VM 重建後也需要一段時間讓總召核對資料，再對全場開放。

## 決定

- **不自動建庫**：`bethere serve` 找不到資料庫檔就拒絕啟動。只有第一次部署設定 `BETHERE_INIT=1` 才建立；`BETHERE_INIT=1` 而資料庫已存在時同樣拒絕啟動。
- **錯誤不是「無效」**：資料庫錯誤、逾時、`SQLITE_BUSY` 一律回伺服器錯誤（客戶端視為離線），只有確實查無有效 Token 才回「無效」。
- **維護模式**：VM metadata `bethere-maintenance=1` 時，`/api/` 只放行 Master Token（與復原碼的「換發 Master」）；其他角色收到伺服器錯誤、保留快照。`/healthz` 與靜態檔照常回應。Master 畫面顯示「維護中」橫幅。服務每次啟動都重讀 metadata，讀不到就不啟動。

## 考慮過的選項

| 選項 | 優點 | 缺點 |
| --- | --- | --- |
| 拒絕啟動 + 維護模式（採用） | 任何失敗都表現為「離線」，不會清掉裝置上的資料 | 第一次部署多一個步驟；維護模式要記得解除 |
| 找不到資料庫就建新的 | 部署最簡單 | 還原失敗時全場收到「無效」並清掉快照 |
| 用 HTTP 狀態碼 401／403 表示無效 | 慣例 | 會場 Wi-Fi 登入頁、代理也會回這些狀態碼，會被誤判為「無效」 |

## 後果

- 好處：最壞情況是全場暫時離線，而不是資料消失。
- 代價：還原後要人工核對並解除維護模式（`operations/runbook.md` 第 2 節程序 2 步驟 4～5）。
- 之後要注意：這些規則都要有自動測試（找不到資料庫、`BETHERE_INIT` 遇既有資料庫、資料庫錯誤回伺服器錯誤、維護模式的放行範圍）。
