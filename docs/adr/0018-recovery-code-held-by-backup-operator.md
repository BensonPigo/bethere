# ADR-0018：復原碼由備援操作者保管，不交給總召

- 狀態：已接受
- 日期：2026-10-22
- 對應：`product/vision.md` V1；`design/access-control.md` 第 2、6 節；修訂 ADR-0003 的保管方式

## 背景

ADR-0003 決定「復原碼與 Master 連結分兩個管道交給當天的總召，例如復原碼印在紙上」。

之後 PO 確認的產品原則 V1（`product/vision.md`，2026-10-22）要求「總召零學習成本……復原碼等維運機制不讓總召接觸」。總召人選未定，可能不是專業婚顧；多保管一張「外流就等同完全接管」的紙，也違反「總召只做核心操作」的方向。兩份文件互相矛盾，願景文件是最上層依據。

復原碼的用途不變（ADR-0003）：換發 Master 連結、Draft 階段改活動日期、活動結束後唯讀匯出。三者都不需要在現場執行：`/recover` 是一般網頁，任何地點都能開啟。

## 決定

- 復原碼由**備援操作者**保管（ADR-0013），不交給總召。
- 總召遺失 Master 連結或懷疑外流時，聯絡備援操作者；備援操作者在 `/recover` 換發新的 Master 連結，再以 LINE 傳給總召。
- 建立活動的指令仍只把復原碼顯示在終端機一次；由開發者交給備援操作者，並與 Master 連結分開保存。
- ADR-0003 的其他內容（只有 Master 一種管理身分、復原碼的三種用途、Master 不能重發自己）不變。

## 考慮過的選項

| 選項 | 優點 | 缺點 |
| --- | --- | --- |
| 交給備援操作者（採用） | 符合 V1，總召完全不接觸；復原碼不在現場，紙本遺失或被拍到的機會較小 | 換發要多聯絡一個人；備援操作者未定時沒有人保管 |
| 照 ADR-0003 交給總召，修改 V1 措辭 | 現場可以自救，不必聯絡別人 | 總召要保管一張外流即完全接管的紙；違反 V1 的本意 |

## 後果

- 好處：總召只需要一條 Master 連結；復原碼的保管與維運權限集中在同一人。
- 代價：Master 連結遺失時，恢復時間取決於能否聯絡到備援操作者。
- 之後要注意：
  - 備援操作者目前未定（RISK-5）。未定期間，復原碼由開發者保管；婚禮當天開發者無法操作，所以記為風險。
  - 備援操作者必須能在活動當天以手機開啟 `/recover`，演練時一併驗證。
