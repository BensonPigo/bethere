# ADR-0006：偏移存在每個 Cue 上，平移留紀錄以精確復原

- 狀態：已接受；平移紀錄的儲存方式由 ADR-0015 修訂
- 日期：2026-10-20
- 對應：`data-model.md` M1、M5、M6、M8；需求 A1～A3、A7

## 背景

時間平移是系統最核心的行為。初版規格用一個全域值 `GlobalOffsetMinutes`。但實際規則包括：固定時間的 Cue 不平移（A2）、總召可取消勾選個別 Cue（A1）、負值平移時已逾時的 Cue 要排除（A3）、進行中的 Cue 不平移。總召也要能復原誤按的平移（A7）。

## 決定

- 每個 Cue 存自己的累計偏移 `offsetMin`；`effectiveStart = scheduledStart + offsetMin`，由伺服器計算後下發。`scheduledStart` 平移時不動。
- 每次平移是一筆有紀錄的操作：`ShiftLog` 記平移量與起點，`ShiftLogEntry` 只記**實際被改到**的 Cue 與套用量。復原就是把套用量反向扣回。
- 「全域偏移」只是顯示值，取目前進行中（或下一個待辦）Cue 的 `offsetMin`，不另存。
- 平移造成固定 Cue 衝突時只警告、不阻擋；負值平移若會讓任一 Cue 早於現在，整次拒絕。
- 整次平移在單一交易內完成，`eventVersion + 1`。

## 考慮過的選項

| 選項 | 優點 | 缺點 |
| --- | --- | --- |
| 每個 Cue 存偏移 + ShiftLog（採用） | 能表達固定、排除、略過；復原精確 | 每次平移寫多列 |
| 單一全域偏移（初版規格） | 一個數字 | 有固定 Cue 或排除勾選時無法表達；與 Cue 時間是兩份真相 |
| 直接改寫 `scheduledStart` | 最少欄位 | 失去原表定時間，無法顯示「（+10）」與事後檢討 |

## 後果

- 好處：任何組合的平移都能精確表達與復原；原表定時間永遠保留，供 C3 事後檢討。
- 代價：演算法有多條排除規則，必須有表格驅動的單元測試覆蓋（`tech-stack.md` 第 4 節）。
- 之後要注意：Live 階段不允許改 `scheduledStart`（P8），否則會與偏移互相干擾。
