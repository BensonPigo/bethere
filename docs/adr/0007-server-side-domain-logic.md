# ADR-0007：領域邏輯與資料過濾只在伺服器

- 狀態：已接受
- 日期：2026-10-20
- 對應：`tech-stack.md` 2.1「平移預覽」；`access-control.md` 第 4、5 節；`sync-and-offline.md` 第 4 節

## 背景

平移有多條規則（ADR-0006），總召在套用前要看到預覽：哪些 Cue 會動、會不會碰到固定 Cue。新人視圖必須「伺服器端就不下發」求助與除錯訊息。各端的時間必須一致。

## 決定

- 平移、狀態轉換、`endsAt` 等領域邏輯**只在 Go 實作一份**。
- 平移預覽由伺服器的「試算」端點計算（同一套演算法、不寫入）；預覽面板每次勾選變更都呼叫它。
- 快照由伺服器依 Role 組裝，只含該角色可見的 Cue 與欄位；伺服器不信任客戶端傳來的角色資訊。
- 時間以伺服器為準：`effectiveStart` 由伺服器算好下發，客戶端只做倒數與時鐘校正。

## 考慮過的選項

| 選項 | 優點 | 缺點 |
| --- | --- | --- |
| 邏輯只在伺服器，預覽走試算端點（採用） | 單一實作、單一測試集；前端不可能算錯 | 預覽需要網路往返 |
| 前後端共用 TypeScript 邏輯 | 預覽不需網路 | 後端要改用 Node；或兩種語言各寫一份、容易漂移 |
| 前端收完整資料再隱藏 | 伺服器簡單 | 違反「伺服器端就不下發」：資料其實已送到裝置上 |

## 後果

- 好處：前後端幾乎沒有共用程式碼，這也是 ADR-0008 能選 Go 的前提。
- 代價：總召離線時看不到平移預覽；但離線時本來就不能操作（ADR-0005），所以沒有額外損失。
- 之後要注意：快照的欄位以後端測試比對 JSON 鍵集合，防止前後端欄位漂移（`tech-stack.md` 2.2「型別」）。
