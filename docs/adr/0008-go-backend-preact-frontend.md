# ADR-0008：後端 Go、前端 Preact + TypeScript

- 狀態：已接受
- 日期：2026-10-20
- 對應：`tech-stack.md` 2.1、2.2

## 背景

一人開發，距第一場使用約 7.5 個月。伺服器要跑在 1 GB 記憶體的小主機上（ADR-0009），API 只有十幾個端點。領域邏輯只在伺服器（ADR-0007），前後端幾乎沒有共用程式碼。前端要在手機上快速開啟，且網址含 Token，不能載入第三方腳本。

## 決定

- **後端**：Go 最新穩定版，標準庫 `net/http`（方法與路徑樣式路由），不用框架；`database/sql` + 手寫參數化 SQL；`log/slog`；前端產物以 `embed` 內嵌進同一個執行檔。伺服器端指令（建立活動、重設復原碼）是同一執行檔的子命令。
- **前端**：TypeScript + Preact，Vite 打包成**單一 bundle**（不用動態 import）；不用路由函式庫，以路徑區分 `/`、`/print`、`/recover` 三個入口。

## 考慮過的選項

| 選項 | 優點 | 缺點 |
| --- | --- | --- |
| Go + Preact（採用） | 單一執行檔、記憶體小、標準庫足夠；前端執行期約 4 KB | 前後端兩種語言；快照型別要手寫兩份 |
| 全端 TypeScript（Node） | 一種語言、可共用型別 | 執行期與相依套件較大；部署要帶 Node 執行環境；共用邏輯的好處因 ADR-0007 而變小 |
| React | 生態最大 | 執行期較大；Preact 的 API 相同，需要時可換 |

## 後果

- 好處：部署單位是一個檔案；小主機上記憶體寬裕（原型實測 VM 約 600 MB 可用）。
- 代價：快照型別在 `web/src/api.ts` 手寫，靠後端測試比對鍵集合防漂移。
- 之後要注意：單一 bundle 是為了讓新版 Service Worker 接手時，舊頁面不會載入已被清掉的分塊（ADR-0010）。
