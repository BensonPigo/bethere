# ADR-0013：當天維運交給備援操作者，不做跨區域備援

- 狀態：已接受（操作手冊為要求草案，待演練）
- 日期：2026-10-20
- 對應：`tech-stack.md` T-E、3.1～3.3

## 背景

開發者本人是當天的新人，無法操作任何維運。系統是單一 VM（ADR-0009），故障時需要有人重建。當天的總召忙著推進流程，不適合同時處理主機。

## 決定

- 指定一位**備援操作者**（不是總召），婚前交付 IAM 權限與紙本操作手冊。權限以 IAM 條件設**到期時間**，婚禮後數天自動失效。
- 手冊只涵蓋兩件事，由備援操作者本人在婚前於另一個暫存專案演練：
  1. 退回上一個發行版。
  2. VM 或磁碟故障時重建 VM（維護模式下還原 → 總召核對 → 解除維護）；超過 30 分鐘或步驟失敗兩次就放棄，改靠離線快取與紙本。
- 整個 `asia-east1` 無法使用時**不切換區域**。
- 婚後重建一次 VM，清除權限期間可能留下的後門。
- 找不到合適人選時，明確接受「當天只剩離線快取與紙本」。

## 考慮過的選項

| 選項 | 優點 | 缺點 |
| --- | --- | --- |
| 備援操作者 + 限時權限 + 演練（採用） | 有人能處理最常見的兩種故障 | 權限等同完全接管，要靠到期時間與婚後重建收尾 |
| 全自動故障轉移（多台、多區） | 不需要人 | 成本與複雜度遠超單場活動；自動化本身也會出錯 |
| 不準備任何維運 | 零成本 | VM 故障就只剩紙本 |
| 交給當天的總召 | 少一個人 | 總召已經滿載，且需要另一套權限 |

## 後果

- 好處：最常見的故障（壞版本、VM 掛掉）在 15 分鐘內可恢復。
- 代價：多一位需要信任的人；威脅表新增「維運權限外流」（`access-control.md` 第 1 節）。
- 之後要注意：手冊目前是要求草案，要寫成腳本、演練驗證，並另行抗辯審查後才定稿。
