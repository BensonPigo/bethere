# ADR-0032：破壞性修改完整記錄，活動日當天鎖住匯入取代與刪除角色

- 狀態：已接受
- 日期：2026-10-24
- 對應：`requirements/stories/m2c.md` US-M-10.4、US-M-11.5、US-M-12.4；`design/api.md` 第 3 節「M2c」；`design/access-control.md` 第 1 節

## 背景

M2c 讓總召在 Draft 階段做三種破壞性修改：貼上匯入取代整份、刪除 Cue、刪除角色。三者都不是「復原上一步」的步驟。刪除角色會讓對方的連結失效，裝置收到 `invalid` 後清掉離線快照。

M2c 的實作前安全審查（P1）指出：

- 活動日當天早上第一次推進之前，活動仍是 Draft（ADR-0020），所以這三種修改都還能用。總召手滑貼上錯的試算表，或外流的 Master 連結一口氣刪掉所有角色，都無法還原。
- 威脅模型原本寫「誤操作：版本號與復原已處理」，對這三種修改不成立。
- 婚禮當天開發者是新人，無法當場處理；整庫還原會連其他活動一起回溯，而且 Litestream 還沒實作（M3a）。

## 決定

- **完整記錄**：被取代或刪除的內容完整寫進操作紀錄。
  - `rundown.import` 記錄被取代的每個 Cue 的欄位，以及它們的指派與角色備註。
  - `rundown.delete` 記錄被刪 Cue 的欄位、指派與角色備註。
  - `role.delete` 記錄角色的名稱、類型、畫面、是否打卡，以及它的指派與角色備註。

  操作紀錄是內部資料表，不進任何快照，隨活動一起刪除（ADR-0011）。紀錄中不含 Token 或其雜湊。不提供還原的畫面；需要時由開發者依紀錄手動救回。
- **活動日當天鎖住兩項**：從活動日 00:00（活動時區）起，「貼上匯入取代整份」與「刪除角色」回 422 `locked_on_event_day`。當天仍可以逐一修改、移動、刪除 Cue，以及新增與改名角色。

## 考慮過的選項

| 選項 | 優點 | 缺點 |
| --- | --- | --- |
| 完整記錄＋當天鎖住兩項（採用） | 當天影響全場的兩種操作直接做不到；婚前的誤操作仍救得回來 | 當天不能整份重貼或刪角色，只能逐一修改 |
| 只完整記錄 | 不限制操作 | 婚禮當天實際上沒有人能當場救回 |
| 提供還原按鈕 | 總召可以自己救回 | M2c 多約兩三天的工作；還原本身也是要審查的寫入 |
| 接受無法還原 | 不用額外工作 | 手滑或外流時整份指派與連結就沒了 |

## 後果

- 好處：婚禮當天，手滑或外流的 Master 連結都無法一次清掉流程表或所有連結。
- 代價：
  - 操作紀錄變大：一次匯入取代約數十 KB，可以接受。
  - 當天要刪角色只能撤銷它的連結（M2b）。
- 之後要注意：
  - 「刪除 Cue」在當天仍可用。一次只影響一個環節，內容也有完整記錄。
  - 操作紀錄裡有角色備註等內容，同樣適用刪除承諾（NFR-5）。
