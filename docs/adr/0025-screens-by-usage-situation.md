# ADR-0025：畫面依使用情況分類，與角色類型分開

- 狀態：已接受
- 日期：2026-10-22
- 對應：`design/screen-design.md` 第 1、4、5 節；`design/data-model.md` Role；`product/vision.md` V2、V5；ADR-0016

## 背景

原本由角色類型決定畫面：類型為 Stylist 就進「新秘模式」（極大倒數、沒有按鈕、螢幕常亮、背景色代表剩餘時間），其他角色進「角色視圖」。

PO 指出，新秘模式服務的其實是一種**使用情況**：雙手在忙、手機放在桌上、只能抬頭瞄。符合這種情況的不只新秘，例如在混音台前的音控、低頭點鈔的禮金組。`requirements/roles-and-scenarios.md` 的角色總覽，本來就是以「手機怎麼拿、能不能看」描述各角色。把畫面綁在角色類型上，也是 ADR-0016 要避免的「只有婚禮才有的假設」。

## 決定

- 畫面依使用情況分為四種：

  | 畫面 | 使用情況 | 預設給 |
  | --- | --- | --- |
  | 免手持畫面（原「新秘模式」） | 手機放桌上、雙手在忙、只抬頭瞄 | Stylist |
  | 快速瞄畫面（原「角色視圖」） | 手機在口袋，拿出來看 2 秒就收回 | Media、StageAV 與其他一般角色 |
  | 平安儀表板 | 不看細節，只想知道順不順利 | Host |
  | 主控台 | 拿平板主動操作 | Master |

- **角色類型**只決定權限與內容（能做什麼、快照含什麼、備註是否預設展開）；**畫面**是角色上的另一個設定 `Role.view`，未設定時依類型的預設。
- 畫面在**建立角色時設定**（目前由 `add-role` 指令，之後由角色管理介面），廠商不需要也不能在手機上切換（V2）。
- 畫面必須與類型相容：Master 只能用主控台、Host 只能用平安儀表板（它們的快照內容不同）；其他類型可選免手持或快速瞄。
- M2a 加上 `roles.view` 欄位（可為空，ADR-0019）與指令參數；M2b 開放攝影、音控時即可直接指定畫面。

## 考慮過的選項

| 選項 | 優點 | 缺點 |
| --- | --- | --- |
| 依使用情況分類，建立角色時設定（採用） | 同一種畫面可給任何符合情況的角色；廠商不用操作 | 多一個欄位與相容規則 |
| 維持由角色類型決定 | 最簡單 | 音控、禮金組等用不到免手持畫面；新角色類型都要重新決定畫面 |
| 由廠商在手機上切換 | 最有彈性 | 第一次開連結的人多一個要理解的東西（V2） |

## 後果

- 好處：免手持畫面的設計（倒數、常亮、無按鈕）不再只屬於新秘；新增角色類型時不必新增畫面。
- 代價：資料庫多一個欄位；角色管理介面之後要能選畫面。
- 之後要注意：
  - 故事代號 `US-ST` 沿用，條件適用於免手持畫面，以新秘為代表情境。
  - 廠商自己切換畫面，等彩排出現實際需要再加。
